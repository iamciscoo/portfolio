# Hero typography and extension hydration

23 October 2026.

## Hydration diagnosis

The warning identifies two extra body attributes: `data-new-gr-c-s-check-loaded` and `data-gr-ext-installed`. Neither is generated by the application. The two plausible causes were an extension changing the DOM before hydration, or an application mismatch involving saved theme state.

A Chrome regression test injects the exact attributes as soon as the parser creates the body. Before the fix, it reproduced the reported warning. A clean browser with the same saved light theme had no hydration warning. This isolates the reported mismatch to the external body attributes.

The layout accepts attribute differences on `body` using `suppressHydrationWarning`. It does not remove extension attributes, disable extensions, disable SSR or intercept console errors. A separate test injects a nested heading mismatch and confirms React still reports it. This follows [React's element-level escape hatch](https://react.dev/reference/react-dom/client/hydrateRoot#suppressing-unavoidable-hydration-mismatch-errors).

## Design audit and direction

The home page already has a clear dark navy photographic hero, a cobalt primary action, Manrope type, rounded buttons and a compact mobile composition. Navigation, the artwork, copy, routes and scroll behavior serve their purpose. The headline's uniform weight and typeface made the greeting and service statement feel interchangeable.

This is a targeted typography refinement for prospective clients, applying the Emil Design Engineering skill. The owner requested upright typography with no italics. Onest carries the heading in a consistent geometric sans serif; a lighter greeting, a blue name and a stronger service line establish hierarchy. The existing Motion behavior stays in place.

| Before                                           | After                                                                  | Why                                                                       |
| ------------------------------------------------ | ---------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Greeting and service use the same type treatment | A lighter greeting, upright blue name and heavier service statement    | Make the name memorable and the service easy to scan                      |
| The whole title is one preformatted string       | Localized greeting and statement share one semantic h1                 | Control visual hierarchy without losing the translated message            |
| Manrope handles every word                       | Onest handles the hero heading; Manrope carries body text and controls | Improve type hierarchy without changing the rest of the site              |
| Browser-added body attributes trigger a warning  | Only the body accepts external attribute differences                   | Address the demonstrated extension conflict while retaining nested checks |

The heading font is self-hosted from the [Google Fonts Onest source](https://github.com/google/fonts/tree/main/ofl/onest), with its SIL Open Font License at `public/fonts/OFL-Onest.txt`. It uses `font-display: swap` and a Manrope fallback. The font supports the Latin and Cyrillic text used by the five translations. The serif font from the rejected draft is removed.

## Validation

- Exact extension-attribute reproduction fails before the body change and passes afterwards. Clean hydration and theme controls also pass.
- Nested mismatch detection remains active.
- Mobile layout and controls are checked at 320px and 390px in all five languages.
- Actual Chrome previews at 1440px, 390px and a 320px French short screen were inspected. The font loads successfully and the primary actions remain visible.
- Preview captures are local verification artifacts in ignored `tmp/hero-refinement/`.
- Final verification passed: 9 focused browser cases, 55 unit/API tests, strict TypeScript, lint and the production build with 81 routes. Independent review found no blocking issues.
